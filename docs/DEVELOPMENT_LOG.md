# SRTP 研发记录

## 2026-09-05：Windows / macOS 环境检测链路

### 本轮目标

在不重写编辑器的前提下，让同一个 Electron 环境页正确识别 Windows 与 macOS，显示视频剪辑所需的硬件和工具状态，并在用户明确确认后执行受限的安装动作。

### 用户可见成果

- 环境页会自动识别 Windows 或 macOS，展示芯片、CPU、内存、磁盘、图形能力和必要工具。
- 检测结果区分“满足”“可用但受限”“不满足”及具体失败原因，不再把探测失败等同于未安装。
- 硬件结果只做风险提示，用户始终可以继续进入主页和编辑器。
- 缺少工具时先展示安装计划，支持取消或确认；成功后自动重新检测，失败时显示手动处理指引。
- macOS 从源码运行时能识别 Homebrew 的 Node.js、npm、Python 3、FFmpeg 与 Metal 能力。

### 关键安全边界

- 页面只能请求白名单工具，不能提交或执行任意命令字符串。
- 每份确认仅绑定一个工具且最多使用一次。
- 取消不会触发安装；安装失败不会被记为成功，也不会自动重试。
- 开发服务仅绑定本机，不再对页面公开通用命令执行或通用安装入口。
- 安装结果不返回令牌、完整环境变量或完整诊断日志。

### 验收缺口修复

- 修正 Windows 捆绑工具的实际文件大小元数据生成，避免发布包因占位值而误报工具不可用。
- 补齐 macOS 版本化 Homebrew 路径的工具探测，使安装后的全量重检能看到 Node.js、npm 和 Python 3。
- 将 Windows 捆绑 Python 纳入报告，并让 npm 缺失时进入 Node.js 修复计划。
- 区分 Whisper 确实未安装与探测过程出错，保留可核对的失败原因。

### 最终验证

- 单元与集成测试：**91/91 通过**。
- Electron 端到端测试：**5/5 通过**。
- 当前 Mac 真实环境只读烟雾测试：**1/1 通过**。
- macOS arm64 目录构建：**通过**。
- 最终整枝审查：**Ready to merge: Yes**。
- GitHub 集成：[Pull Request #1](https://github.com/trydays/srt/pull/1) 已通过普通合并提交进入 `main`，仓库默认主页已展示本轮新版本。

> 上述数量是 2026-09-05 的验收快照，会随测试集演进；README 不依赖这些易过时数字。

### 明确延期

以下工作不属于本阶段验收，不阻断集成：

- 在真实 Windows 设备上运行烟雾测试。
- 可选 CUDA 能力检测。

## 2026-09-07：字幕视频导出真实整链验收

### 本轮目标

把周期 1 的 FFmpeg 渲染与周期 2 的编辑器接入串成真实可用链路，并跑冻结回归，确认“给视频加字幕 → 导出烧录 MP4”达到最低可用。

### 用户可见成果

- 编辑器右上角“导出视频”入口走系统原生另存为，把已应用字幕烧进 MP4。
- 导出期间显示真实进度、可取消，仍可播放 / seek；字幕修改未应用时会阻止导出。
- 导出全程保护源文件与已有目标文件，不覆盖。

### 实际实现

- preload 暴露 `resolveVideoSource`、`startVideoExport`、`cancelVideoExport`、`onVideoExportProgress` 四个窄方法。
- 主进程只维护一个普通 `activeExport` slot，覆盖对话框、路径处理、进度转发与失败码收口；无 Job 类、队列或任务中心。
- 页面只维护一个 `window.isExporting`，冻结写入口；无通用锁或事件总线。
- 渲染服务固定 MP4 / H.264 / AAC / yuv420p，用 libass 烧录白字 + 0.72 半透明黑底。

### 最终验证

- 冻结回归：`node --test tests/environment.test.js tests/render-recipe.test.js tests/video-export.test.js tests/main-entry.test.js` → 56 通过 / 0 失败 / 1 条件跳过。
- 编辑器 E2E：`npx playwright test tests/e2e/video-export-flow.spec.js tests/e2e/auto-subtitles-flow.spec.js` → 9 通过 / 0 失败（30.9s）。
- 真实渲染（ffmpeg-full 9.0.1，`/opt/homebrew/opt/ffmpeg-full/bin`）：
  - 横屏 640×360，H.264 + AAC，4.0s，字幕区 `YMAX=236` 证明白字已烧录。
  - 竖屏 360×640，H.264 + AAC，中文长句烧录（`YMAX=242`），音频保留。
  - 真实取消：返回 `cancelled`，无伪产物文件，源文件字节数不变。

### 明确延期 / 限制

- 真实 GUI 手动整链（导入真实视频 → 本地 CLI 识别 → Whisper 生成 → 点导出 → 外部播放器人工确认）仍需在真实窗口点验；本周期用真实 ffmpeg 渲染与自动化 E2E 分别覆盖渲染与交互，未重复人工矩阵。
- 带显示矩阵旋转元数据的手机竖屏：官方 ffmpeg 无法生成忠实夹具（`-display_rotation` 只会物理旋转、不写矩阵），已用物理 360×640 竖屏端到端验证；该元数据路径仅由 `probeMedia` 维度计算覆盖，留待真实手机片段复验。

## 2026-09-07：AI 效果配方实时推导与项目上下文注入

### 本轮目标

让本地 CLI 不再从“预设效果名”查表，而是收到用户想要的效果后，实时推导出由底层能力（积木）组成的有序步骤、每个步骤的参数与时间区间；同时把编辑器当前项目状态作为上下文注入，使相对描述（如“片尾淡出”）不必再向用户追问已在环境中存在的信息。

### 范围控制

- 只实现“实时推导”这一段：参数化能力注册表、分解提示、输出协议、白名单/范围校验；不涉及渲染执行与导出。
- 上下文注入分两步落地：先注入视频事实（总时长 / 分辨率 / 播放头），再注入已执行编辑命令与字幕轨摘要。

### 实现结构

1. 积木升级为“带参数模式的能力声明”：`CAPABILITY_SCHEMAS` 六个积木（字幕、淡入、淡出 + color.grade / texture.grain / vignette），参数只支持 number，带 min/max/default/description，统一 start/end（秒）。
2. 提示词只教分解方法，不教“效果 → 固定配方”映射；无 few-shot 样例。
3. 输出协议固定为 clarify / instruction.steps，steps 数组顺序即执行顺序。
4. 校验只做白名单 + 参数模式检查：未知能力、未声明参数、越界值、非法时间一律抛 `LOCAL_CLI_INVALID_INSTRUCTION_OUTPUT`。

### 实际实现

- 参数化注册表与按 schema 的 `parseInstruction` 校验；真实本地 CLI 冒烟复现中发现 Claude Code 推导约 20s，原 15s 转换超时会被误杀，已将转换上限放宽至 60s。
- 渲染层在每次指令转换前冻结项目快照：视频事实 + 已执行编辑命令（时间轴结构化记录）+ 字幕轨摘要（按段给出序号 / 起止秒 / 文字，最多 500 段、每段 80 字），经 IPC → 主进程 → 本地 CLI 服务 → 提示词。
- 时间轴效果标记升级为保留 `capability + params` 的结构化条目，右键删除后上下文同步消失；字幕轨取已应用文字。

### 最终验证

- 全量单测：179 项中 178 通过 / 0 失败 / 1 条件跳过。
- 编辑器相关 E2E：`local-cli-effect-flow + auto-subtitles-flow` → 10/10 通过。
- 直接调用 Claude Code 的真实冒烟返回符合契约的多积木配方：color.grade / texture.grain / vignette / fade.out 组合，耗时约 20.7s（应用内已放宽超时）。

### 明确延期 / 限制

- 色偏 / 颗粒 / 暗角尚无渲染执行方：它们能推导、能通过解析，但不会落到时间轴，也不会进入“已执行编辑命令”，待渲染能力接入。
- 应用内“第二条指令自动读取第一条结果”的人工点验尚未最终确认（自动化已覆盖提示词与 IPC 透传）。
- 时间轴效果仍为会话内存状态，刷新后不恢复标记；字幕轨与对话记录已持久化。

## 2026-09-07：通用执行链周期 1 — 统一状态与字幕迁移

### 唯一目的与边界

按照已确认的周期 1 计划，建立最小统一执行主干，并让现有全片字幕完整经过它。只接入 `subtitle.generate@1`，单条 Recipe、唯一字幕轨、一次撤销和 `source.video@1 → visual.subtitle@1` 线性图；不进入周期 2，不新增 npm 依赖、数据库或 IPC，不改变颜色与布局。

### 内部完成度

- 能力注册表将声明与 prepare / toEdit / toGraph / toTimeline / preview / toExport 绑定；缺少实际 Adapter 或路由元数据的能力不对 AI 公开。提示与解析共用此目录，删除未接通效果的执行承诺。
- `ProjectEditing` 是已应用编辑的唯一写入入口。整份 Recipe 校验、准备结果、候选图编译完成后，再校验 revision 并一次保存文档与撤销记录；中途失败不改旧状态。
- `EditDocument` 持久化字幕内容，`RenderGraph` 派生预览与导出；时间轴和下一轮 AI 上下文从同一 revision 重建，并保留播放头信息。
- 旧字幕 key 保留且仅读迁移，原 `subtitle-state.js` 文件与旧格式测试保留，编辑页停止加载旧 store。未应用草稿保存到独立 sidecar。
- Tasks 3–5 的界面切换、提示词和导出接入合为一个集成提交，避免中间提交出现新旧状态接口不匹配。实现后的核查只修复既定链路问题，没有新增效果或平台能力。

### 用户可见成果

- 生成字幕后可在现有文稿区统一修改；“保存”仅存草稿，“应用”才改变视频字幕。
- 重复生成只替换一条字幕轨，整次撤销可恢复之前应用的文字与草稿。
- 刷新后恢复时间轴、字幕与可用撤销；对话历史保存失败不会把已提交编辑误报成失败，缺失的撤销入口可从项目状态恢复。
- 导出使用当前图中的已应用字幕，保留现有进度、取消、编辑器冻结、原生另存为与源文件保护。
- 未接通组件拖入只说明当前限制，不再产生假编辑记录。

### 审查发现并修正

- 反问的后续消息也必须通过草稿保存检查，保存失败不清空用户输入。
- 草稿清理失败不回滚已应用字幕；过期草稿不会在刷新后被误用并持续阻塞编辑。
- 刷新后先等待当前视频就绪，再翻译与执行；重新上传会清除旧路径。
- 导出等待项目恢复期间防止重复点击，并在等待结束后重查草稿、项目、源视频与正在执行的编辑。
- 测试使用真实临时文件路径模拟桌面导入；内存上传无本地路径，不再被测试当作可执行素材。
