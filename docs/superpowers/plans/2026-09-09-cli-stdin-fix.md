# CLI 输入关闭与退出核查实施计划

> 执行方式：本轮用户已批准两点最小边界；测试先行，独立复核。不另建分支，不提交或推送。

**目的：** 修复已确认的 CLI 输入未结束缺陷，并用实际事件确认收到回复后是否仍卡在退出阶段。

**设计：** 保留现有 `createLocalCliService` 与解析器。输入仍由 argv 传入；默认翻译器关闭子进程 stdin。先取得 exit/close 证据，不能在任意错误后接受部分 stdout。

**边界：** 60 秒、64KiB、提示词、模型配置、Remotion 均不变；不新增监控、重试或平台模块，不上传参考视频或识别文字。只做无敏感内容的最小真实调用与必要本地回归。

**额度与退出：** 30 分钟窄修复上限；约 15 分钟必须有可核验测试／调用结果。输入真实回归通过、退出核查结论明确后结束；若需要改变完成协议或全局配置，先报告成本与依据。

## 1. 输入生命周期（src/local-cli.js、tests/local-cli.test.js）

- [x] 用真实 Node 子进程等待 stdin EOF 后输出合法 clarify JSON，经过生产服务/default translator。底层注入仅替换外部可执行程序与测试等待额度，不模拟 EOF。
- [x] 缺陷代码必须先失败，原因是没有收到 EOF；测试限时不改变生产 60 秒。
- [x] 将 `execFile(...)` 返回的子进程保留下来，调用 `child.stdin.end()`，移除无效 stdio 选项；兼容现有不返回子进程的测试注入。
- [x] 执行 `node --test tests/local-cli.test.js`，同时保留真实超时／非法输出不能成功的保护。

## 2. 退出核查与验收

- [x] 临时诊断只记录启动、首次 stdout、stdout/stderr end、exit、close 的时刻与退出状态；错误只留脱敏类别。
- [x] 在相同 60 秒配置下运行一个无视频内容的最小真实请求，明确分辨模型回复与进程成功退出。
- [x] 必须依据证据决定是否需要第二处修复；没有证据不改超时或接受错误输出。
- [x] 主代理核对差异／结果、独立审查、更新研发日志；分别报告内部完成与用户可见状态，不把连接测试当完整剪辑验收。

## 实测结果

EOF 回归先因 500ms 内没有收到 EOF 而失败，修复后约 28ms 通过。最终 CLI 与协议测试 59/59，包含合法输出后非零退出／超时仍拒绝的真实子进程检查。独立聚焦审查通过。

退出核查探针 first stdout 48,641ms、exit 55,008ms、close 55,009ms，正常退出；修后生产服务入口 first stdout 40,884ms、exit 46,109ms、close 46,110ms，收到合法 clarify 并通过解析。后一探针没有自行关闭 stdin，而由实际产品代码完成；唯一诊断安全覆盖是只读权限。两次均无视频／识别文字，无全局配置变更。

有证书／WebSocket 重连和 MCP transport 错误类别，具体信任链原因未查明。本轮未重现固定退出死锁，不改完成协议、不忽略进程错误、不延长 60 秒。完整视频提炼／导出验收仍开放；本地窄修复结束，不自动继续配置／网络改造或完整模型重跑。
