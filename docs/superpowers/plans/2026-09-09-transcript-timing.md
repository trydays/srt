# 自动时间定位：收缩后的执行计划

执行状态：两步均完成。第二步开工时声明 15 分钟检查上限；真实用户视频一次验收通过，产出 MP4 并完成撤销。相关 Node 98/98、Python 3/3、固定桌面 9/9、真实桌面 1/1。精度不作统一承诺，详见研发日志本日“细化时间接入完成”记录。

## 目的
用现有模型取得更细语音时间，传给 AI，让用户无需手填时间戳即可完成要点弹出。

## 第一步：取得并传通时间（首个主动工作检查上限 30 分钟）
- Python 分析模式启用 word_timestamps，按标点和停顿生成 timingSegments；没有可靠句界时保留词单元。
- 原字幕 segments 不变；服务、IPC、前端将 timingSegments 传入既有 transcript。
- 分句时间取词起止，不均分，不捏造。词数据不可用则保留原段，不能冒称精确。
- 交付用户视频的可阅读时间清单；相关字幕兼容和传递测试通过。
- 不迁移历史项目；旧字幕／旧缓存维持原行为，真实验证使用新项目新请求。
- 先写复现测试，再实施。必要的接口校验保留，不扩展通用对齐平台。
- 到检查点报告实际投入、内部进展和可查看结果；不因尚未完善无限延长。

## 第二步：同一视频真实验收
- 第一步完成后按实际剩余工作设本段上限并说明，再执行。
- 新项目、同一 17.6 秒视频、同一要点请求，一次真实链路、无自动测试重试。
- 检查 AI 得到细时间、不向用户索要时间戳、按原文生成效果、可导出和撤销。
- 沿用原样式；不增加遮挡／精度／历史恢复的新验收门槛。
- 保存成片和实际时间偏差，用户观看判断是否够用；不预先承诺 0.5 秒。
- 若 AI 反问或失败，如实报告；不伪造成功、不新增模型、不无限重试。

## 接口
- generate({videoPath, includeTiming:false}) 维持 {segments}。
- includeTiming:true 返回 {segments, timingSegments}；两种数组均为 {start,end,text}。
- Python 中词数据只用于生成细分时间，避免引入重复持久化和新项目结构。
- 默认字幕调用无新增参数；分析调用显式请求 includeTiming。
- timingSegments 缺失可退回 segments；仍必须遵守旧时间／文本校验。
- 保持现有 Render Recipe 的 range，不引入引用 ID 绑定协议。

## 成本与边界
支撑工作以 25% 为检查阈值；阶段过半应有可检查成果。只报告实测投入，不将管理额度当工期承诺。不把已有模型和渲染复用再次计作提速收益。
不改已认可 UI／样式，不加入强制对齐模型、说话人识别、波形编辑器、项目迁移或新效果。提交／推送另按用户指令。
本计划优先于前版三周期、90 分钟累计额度及 0.5 秒精度门槛。
