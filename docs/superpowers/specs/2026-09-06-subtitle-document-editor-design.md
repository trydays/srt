# 字幕文稿编辑与任务折叠设计

日期：2026-09-06

状态：设计已由用户确认，待实施计划

## 1. 阶段冻结

### 唯一目的

把自动生成后的字幕校对从“在时间轴中逐块选择、逐句保存”改为一个位于左侧对话区的连续文稿编辑流程，并在任务完成后压缩状态卡占用。

本阶段只改善已经跑通的自动字幕链路，不扩展字幕识别、渲染或导出能力。

### 可直接查看或运行的成果

1. 用户输入“给视频加字幕”时，同一张状态卡在执行期间显示“转换编辑指令”和“生成字幕”两行进度。
2. 成功后状态卡自动折叠为一行摘要，字幕文稿编辑区自动打开。
3. 用户在同一个连续文稿中访问全部字幕，不分页、不依赖时间轴逐条选择，并可连续校对多个段落。
4. 编辑区右上角提供真实可用的“保存”和“应用”按钮。
5. 用户发送下一条指令时，未保存修改先保存为未应用草稿，字幕区随后收起，新任务进度进入视野。

### 明确不做

- 不重新断句、合并或拆分字幕段落。
- 不编辑开始时间、结束时间或字幕持续时间。
- 不做搜索替换、批量删除、AI 校对、翻译或敏感词检测。
- 不做字幕样式、说话人识别、多语言轨、多版本历史或通用撤销栈。
- 不改造为完整多轨时间轴，也不解决其他特效的轨道堆叠问题。
- 不调用 FFmpeg 烧录字幕，不生成新视频文件，不改造最终导出链路。
- 不建设虚拟列表、复杂缓存或移动端专用布局；只有真实测量证明普通列表无法满足当前项目时才另立优化任务。
- 不重构与本交互无关的组件库、Agent 协议、Whisper 模型准备或转录进程。

### 时间与额度上限

- 当前设计阶段硬上限：一份设计说明、一个可点击预览和一次设计文档提交；完成后立即停止设计扩展。
- 下一实施阶段的时间预算在实施计划中单独冻结，未经用户确认不开始实现。
- 实施时支撑性工作不得超过阶段投入的 25%；本功能不应新增后端服务、模型或渲染基础设施。
- 任一支撑模块超过实施计划估算两倍，立即停止并报告。

### 立即结束条件

六项用户可见验收全部通过后立即结束：生成后自动打开、完成卡自动折叠、整篇可编辑、保存后刷新仍在、应用后预览更新、失败时不丢失旧字幕或草稿。

## 2. 现状与问题定义

当前“保存”按钮不是硬编码的空按钮。它已经连接 `subtitleStore.updateText()`，自动测试和真实复跑也证明保存后刷新仍能保留文字。

实际问题是交互入口和反馈：

1. 用户必须先在狭窄的时间轴字幕块中找到某一句。
2. 一次只能打开一个单行输入框，校对数百条字幕需要反复选择。
3. 保存反馈不明显，因此真实功能在使用感受上像没有生效。
4. 每条任务长期保留两行完成详情，占用对话历史空间。

本设计解决的是“批量校对入口与状态密度”，不重复建设字幕存储或转录能力。

## 3. 方案选择

### 采用：成功卡下方的单一字幕文稿编辑区

编辑区视觉上位于最新有效的“字幕已生成”结果之后，但它代表当前项目字幕，而不是某一条历史消息的旧版本。任一时刻只有一个字幕编辑器实例。

优点：

- 对话、执行结果和字幕校对处于同一阅读路径。
- 不遮挡右侧视频与下方时间轴。
- 复用现有项目字幕状态和左侧滚动区域，改动范围最小。

### 不采用：每条字幕一个编辑卡片

几百条字幕会产生大量边框、按钮和独立操作，继续增加认知负担，也无法满足“在一个地方集中访问全量字幕”的目标。

### 延后：整个左栏切换为独立字幕页面

独立页面能获得更大列表空间，但会隐藏对话历史并增加返回导航、页面状态和新任务打断处理。当前阶段不需要这层复杂度。

### 延后：纯文本自由重排并自动重新对轴

允许任意增删换行后，原字幕段落与时间码不再一一对应，必须新增重新断句和重新对齐算法。这会把前端校对优化扩大为字幕处理系统，不进入当前阶段。

## 4. 左侧状态卡

### 执行中

状态卡完整显示两行：

1. 转换编辑指令：转换中 / 成功 / 失败。
2. 生成字幕或应用编辑：等待 / 生成中 / 应用中 / 成功 / 失败。

用户可以直接看到任务当前停在哪一步，不产生额外通知卡。

### 成功

所有使用这张两行状态卡的自然语言编辑任务进入最终成功态后，都自动折叠为一行摘要。字幕任务例如：

`✓ 字幕已生成 · 315 条 · 10:32`

摘要保留展开控件。用户手动展开后仍可查看两步详情和现有撤销入口。重新进入项目时，历史成功卡默认折叠。

### 失败

失败卡不自动折叠，必须保留失败步骤和现有可读恢复提示；本阶段不新增通用重试或恢复系统。字幕生成失败时不打开字幕编辑区，也不覆盖当前字幕。

## 5. 字幕文稿编辑区

### 呈现方式

- 字幕生成成功后自动打开。
- 编辑区标题为“编辑全部字幕”，同时显示段落数量。
- 全部字幕位于一个限高、可独立滚动的文稿表面中；不为每句增加卡片、保存按钮或独立弹窗。
- 每段文字旁显示弱化的只读开始时间，帮助用户定位，但时间码不参与编辑。
- 编辑区保持在左栏可用空间内，不产生横向滚动。左栏窄于 260px 时，标题信息占第一行，“保存”和“应用”在第二行右对齐；只读时间码移到对应文字上方。
- 时间轴保留紧凑字幕块作为位置概览，但不再承担主要文字校对。
- 删除时间轴下方现有的单句输入框和旧保存按钮，避免两个编辑入口产生不同步状态。

### 分段保护

视觉上只有一个文稿编辑器，内部由按字幕段落 ID 标识的无边框可编辑段落组成；不是需要逐条打开的卡片或弹窗。全部段落同时存在于同一个滚动表面。每段文字可以直接编辑，但第一版禁止：

- 使用回车新增段落。
- 删除两个字幕段落之间的边界。
- 粘贴多行文字改变段落数量。
- 修改段落 ID、开始时间或结束时间。

点击任意段落即可编辑；`Tab` 移至下一段，`Shift+Tab` 返回上一段。回车不创建新段落，粘贴到单个段落的换行会转换为空格。用户无需逐条打开或逐条保存，系统仍能稳定地把每段文字写回原时间范围。

## 6. 保存与应用语义

两个按钮位于字幕编辑区右上角，必须产生不同且可观察的结果。

### 保存

- 把整份当前文稿保存为该项目的字幕草稿。
- 不改变时间轴和视频预览正在使用的已应用字幕。
- 成功后显示“草稿已保存 · 尚未应用”。
- 保存后“保存”禁用；因为草稿与已应用版本不同，“应用”保持可用。

### 应用

- 先校验整份文稿，再把候选文字一次性写入当前字幕轨。
- 同时保存项目状态、更新字幕时间轴块和视频预览。
- 成功后清除未应用草稿，显示“所有修改已应用”，两个按钮均禁用。
- 不运行 FFmpeg，不生成视频文件。

### 编辑状态

- 未修改：显示“所有修改已应用”，两个按钮禁用。
- 修改后：显示“有未保存更改”，两个按钮启用。
- 已保存未应用：显示“草稿已保存 · 尚未应用”，“保存”禁用，“应用”启用。
- 状态必须使用文字表达，不能只依赖颜色。

## 7. 新指令与自动收起

当字幕文稿打开时，用户发送下一条编辑指令：

1. 若没有未保存修改，直接收起字幕编辑区。
2. 若有未保存修改，先保存为未应用草稿。
3. 保存成功后收起为“编辑字幕 · N 段”标题栏；若存在草稿，标题栏标记“草稿未应用”。
4. 新的用户消息和任务状态卡进入视野。
5. 用户可随时重新展开字幕区继续编辑或应用草稿。

本阶段唯一的隐式保存触发点是“发送下一条编辑指令”。自动保存不等于自动应用，草稿不会在用户不知情的情况下改变视频预览。

手动折叠字幕区或切换“对话 / 组件”只隐藏界面并保留当前页面内的候选文字，不触发保存；折叠标题继续显示“有未保存更改”。刷新、关闭页面或切换项目之前，用户仍需主动点击“保存”或“应用”。本阶段不新增关窗拦截或跨页面自动保存系统。

若自动保存失败，不发送下一条指令、不收起编辑区，并显示“字幕草稿保存失败，请重试”，防止用户误以为修改已经安全保存。

## 8. 项目状态模型

沿用现有项目级字幕存储，不建立新的服务或通用版本系统。状态扩展为：

```json
{
  "segments": [
    {"id":"segment-1","start":0.42,"end":2.18,"text":"已应用字幕"}
  ],
  "draft": {
    "segments": [
      {"id":"segment-1","start":0.42,"end":2.18,"text":"草稿字幕"}
    ],
    "savedAt": 1788680208000
  },
  "undo": {
    "requestId": "request-2",
    "segments": [],
    "draft": null
  }
}
```

规则：

1. `segments` 始终是时间轴和视频预览使用的已应用版本。
2. `draft` 只在已保存文字与 `segments` 不同时存在。
3. 文稿打开时优先展示 `draft.segments`；没有草稿时展示 `segments`。
4. 保存只写 `draft`。
5. 应用采用“校验候选数据 → 一次写入 `segments` → 清除 `draft`”的顺序，不做逐段部分提交。
6. 字幕重新生成成功前，把当前 `segments` 和 `draft` 一起保存为本次生成的一层快照；新的生成结果成为 `segments`，当前 `draft` 清空，避免把上一版草稿错误映射到新的段落 ID。
7. 现有“撤销本次字幕生成”仍只保留一层。撤销时同时恢复快照中的 `segments` 和 `draft`，避免已经保存的草稿静默丢失。本阶段不为每次文字编辑增加撤销历史。

## 9. 数据流

### 生成成功

1. Agent 把自然语言转换为现有 `generate_subtitles` 指令。
2. 本地字幕流程返回全部有效片段。
3. 编辑器把替换前的 `segments` 和 `draft` 一起保存为本次生成快照，再一次替换已应用 `segments` 并清除当前草稿。
4. 状态卡进入成功态并自动折叠。
5. 单一字幕文稿编辑器读取新 `segments` 并自动打开。

### 保存草稿

1. 用户在文稿内修改一个或多个段落文字。
2. 界面只维护当前候选文稿并显示未保存状态；视频预览仍读取 `segments`。
3. 点击“保存”或发送新指令触发整份候选文稿校验。
4. 校验通过后按项目写入 `draft`，不修改 `segments`。

### 应用草稿

1. 用户点击“应用”。
2. 编辑器校验每段 ID、时间和非空文字，并确认段落集合与当前字幕一致。
3. 候选文稿作为一个整体写入 `segments`，随后清除 `draft`。
4. 字幕块和画面预览统一重新渲染。

## 10. 错误处理

- 空白字幕段：在文稿中标出对应段落并提示“字幕文字不能为空”；不保存、不应用。
- 段落集合或 ID 不一致：提示“字幕已经变化，请重新载入当前字幕后再编辑”；不部分写入。
- 草稿保存失败：保留当前文稿和未保存状态，不收起、不继续发送新指令。
- 应用失败：保留当前候选文稿；已保存过的草稿继续显示“尚未应用”，未保存内容继续显示“有未保存更改”；时间轴和预览保持上一已应用版本。
- 字幕生成失败：沿用当前失败卡，不打开空编辑器，不改变已有字幕或草稿。
- 页面重新进入：若项目存在草稿，恢复草稿并在折叠标题标记“草稿未应用”；预览仍显示已应用版本。

错误反馈放在编辑区标题或对应段落附近，不额外堆叠新的对话消息。

## 11. 代码职责边界

### 字幕状态模块

负责已应用字幕、草稿、保存、应用和现有一层生成撤销。它不读取 DOM，也不处理任务卡折叠。

### 字幕编辑器模块

负责把当前项目字幕呈现为统一文稿，维护编辑状态，调用保存或应用接口，并统一刷新文稿、字幕块和画面字幕。

### 对话与任务状态模块

负责两行执行状态、最终卡折叠、失败展开，以及发送新指令前请求字幕编辑器安全收起。它不直接修改字幕数据。

### 页面结构与样式

只增加单一字幕文稿容器、统一操作按钮和折叠样式。继续复用当前暖白背景、陶土橙主色、边框、圆角和文字层级，不修改产品颜色。

## 12. 测试与验收

### 单元测试

- 保存只创建或更新 `draft`，不改变 `segments`。
- 应用把完整候选文稿写入 `segments` 并清除 `draft`。
- 空白文字、段落 ID 变化或段落数量变化整体失败，不产生部分写入。
- 重新生成把旧草稿移入本次生成快照，并清空新字幕的当前草稿，避免不同段落 ID 混用。
- 重新生成前的一层快照同时包含已应用字幕和已保存草稿；撤销生成时两者一起恢复。
- 草稿和已应用字幕继续按项目 ID 隔离。

### 编辑器流程测试

1. 字幕生成期间显示两行进度；成功后卡片自动折叠且编辑区自动打开。
2. 一个非字幕编辑任务成功后也自动折叠；失败任务保持展开。
3. 失败卡保持展开，旧字幕不变，编辑区不被空结果替换。
4. 一个文稿表面同时显示全部固定字幕片段，不出现每句独立保存按钮；`Tab` 和 `Shift+Tab` 可以连续移动编辑焦点。
5. 连续修改多个段落后点击“保存”，刷新页面仍恢复草稿，预览仍显示旧的已应用文字。
6. 点击“应用”后，草稿消失，时间轴、画面字幕和项目存储同步更新；无需先点击“保存”。
7. 有未保存修改时发送新指令，先保存草稿、再收起编辑区并显示“草稿未应用”。
8. 模拟草稿保存失败时，新指令不发送、编辑区不收起、当前文字不丢失。
9. 重新生成后撤销，能够同时恢复生成前的已应用字幕和已保存草稿。
10. 时间轴下方旧单句编辑器和旧保存按钮不再出现。

### 本机可见验收

不重复下载模型，也不要求再次跑完整长视频转录。使用现有已生成字幕的项目或固定测试片段，手动验证：

- 数百段字幕能在左侧文稿区滚动查看。
- 修改多个位置后，保存、刷新、应用和预览结果符合定义。
- 发送下一条指令时草稿安全保存并自动收起。
- 左侧状态卡折叠后明显减少历史记录占用。

只有本次修改触及真实字幕生成入口时，才补跑一条短视频生成回归；不把前端交互验收扩大为模型和 FFmpeg 的重复安装测试。

## 13. 完成度报告

### 用户可见完成度

- 一次看到并校对整份字幕。
- 统一保存草稿或应用到视频预览。
- 下一条指令不会覆盖未保存修改。
- 已完成任务不再长期占用两行历史空间。

### 内部完成度

- 项目字幕明确区分已应用版本与未应用草稿。
- 保存、应用和自动收起各自有单一职责。
- 失败路径保持原字幕和候选文稿，不发生部分提交。

内部工作只服务上述用户可见结果；本阶段不以平台化、通用字幕系统或极端恢复能力为目标。
