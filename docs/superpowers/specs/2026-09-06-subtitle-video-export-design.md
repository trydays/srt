## 2. 产品结构与阶段划分

长期结构为两条来源、同一执行流程：常见稳定功能由产品人工决定做成组件；未预设效果由 AI 推敲并生成声明式剪辑配方。组件来源和 AI 来源最终共用项目状态、预览、撤销与导出。

本期只交付字幕这一项真实能力。配方是从现有已应用字幕创建的不可变导出快照。现有 subtitle-state 仍是字幕文本、草稿、撤销的唯一存储来源；不新增一份持久化配方造成双写。

当前 local-cli 的字幕指令继续复用。完整 AI 配方生成、原子能力组合、更多真实效果分别在后续有明确样例时计划。不存在使用统计、自动晋升、自动建设效果库的任务，也不预填未来效果名。

## 3. 用户操作与界面

- 编辑器右上角固定“导出视频”。只在用户点击后渲染。
- 字幕“保存”只持久化草稿；“应用”更新当前字幕与预览。新生成字幕沿用现有自动应用行为，不强迫用户再点一次应用。
- 有未保存或已保存但未应用的字幕时，导出提示“字幕修改尚未应用，请先点击‘应用’”，展开现有字幕编辑区。
- 当前存在淡入等尚未实现真实渲染的时间轴项目时，列出实际名称并阻止导出，不静默忽略。已经删除的时间轴项目不因历史对话仍存在而被误判。
- 字幕/指令正在生成时不可开始导出。当前视频路径缺失、无法播放、不是当前项目实际加载的视频时不可开始导出。
- 原生另存为窗口默认源文件目录、文件名“原文件名-已编辑.mp4”。用户可修改文件名与目录。
- 本期只创建新文件。源文件及其他已有文件均不覆盖；重名时提示换名。取消另存为不启动渲染。
- 输出固定 MP4，内部使用 H.264、AAC、yuv420p；不增加格式、编码器或画质设置。保持正常输入的画面尺寸与时间节奏，不擅自改变帧率。
- 导出按钮显示真实百分比。点击展开锚定式小浮层，包含进度、目标文件、取消按钮。收起不影响运行，不向对话历史追加多条进度消息。
- 准备阶段显示“准备导出”；渲染阶段显示“导出中 N%”；文件提交阶段显示“正在保存”，此时取消按钮禁用；最终显示成功文件路径、取消或可读错误。
- 不模拟百分比。只有子进程正常结束、文件验证及最终保存完成后才显示 100% 和成功。
- 保留现有页面色彩、对话位置与布局，仅增加已确认的导出入口与浮层。

### 导出期间允许和禁止的行为

允许播放/暂停、拖动播放进度、调整监听音量、浏览历史、展开收起已有内容和进度浮层。

冻结改变项目结果的行为：发送指令、字幕内容编辑/保存/应用/撤销、添加/删除时间轴项目、重新上传视频。暂停首页跳转、切换和关闭项目标签，避免丢失当前导出控制；这不是后台导出能力。

锁在另存为前建立，取消对话框、失败、取消或成功后均恢复。已有指令运行中不建立导出锁。UI 禁用与实际写操作入口都检查同一个锁，不能仅将按钮变灰。

正常关闭应用时结束当前导出，等待渲染子进程退出和本任务临时文件清理后再关闭。不建立强制退出/系统断电恢复机制。

## 4. 预览、字幕状态与导出保持一致

### 视频来源

目前代码按项目保存 video.path，但预览从 IndexedDB 的全局 current_video 取 Blob。先上传 B 再打开 A 时可能出现“看到 B、导出 A”。

本期局部修正桌面编辑器：通过主进程校验当前项目路径并返回 file URL，播放器加载该源，加载成功后记录当前项目 ID 和规范化路径；识别与导出读取同一个已加载路径。浏览器预览仍可使用 Blob，不迁移 IndexedDB，不建立资产数据库。桌面路径失效不得回退到另一项目的全局 Blob 并继续导出。

### 字幕状态

导出读取现有 store.get(projectId).segments 的深拷贝，不读取 draft 或编辑区的候选文本。导出前检查 hasPendingChanges()，建立锁后才获取快照。

### 字幕外观

使用一份固定字幕样式定义，保留当前白字、半透明黑底、居中靠下的视觉。按视频实际画面内容区定位和缩放，排除 letterbox 黑边；预览和烧录使用同一中文字体和相同的换行结果。

基准为现有 800×450 预览中的 16px 字号、底部 7%、最大宽度 84%、黑底不透明度 0.72。在不同尺寸下按画面高度缩放。当前 Mac 的字体选择需在周期 0/1 样片上验证，不在本期引入字体下载器。

“与预览一致”验收为文字、起止时间、颜色、相对位置、相对字号和换行一致。浏览器与 libass 的抗锯齿、圆角边缘不设逐像素相同比较；若需要增加新渲染技术才能匹配，停止报告，不暗中改变产品颜色。

换行是导出快照中的布局结果，不写回用户字幕文本。字幕状态仍保存原始整句；预览和导出共同使用根据当前视频尺寸及已加载字体测量得到的行数组。

## 5. 模块与最薄接口

仓库根目录：/Users/mac/Documents/项目/SRTP。遵循现有原生 JavaScript、Electron 和 node:test 结构。

### 配方模块：src/render-recipe.js

同一纯模块供 Node 与页面使用（CommonJS + 浏览器全局 SRTRenderRecipe）。职责为字幕快照构建和校验，固定版本和当前唯一能力；不做插件加载或通用滤镜语言。

约定输入：version: 1，steps 数组，唯一能力标识 subtitle.burn@1。每条字幕包含 id、以秒为单位的 start/end、原始 text，以及可选的已排版 lines。缺省 lines 表示一行 text；编辑器为长句计算显式 lines。配方不包含源路径、目标路径、FFmpeg 参数或脚本。

允许 steps 为空，此时做普通 MP4 导出；只有字幕导出是本期主验收目标。只允许一个字幕 step，不支持的 capability 或版本必须明确失败。时间必须有限、非负且 end > start；实际起止不得超过主进程读取的源视频时长。微小的边界舍入误差可按一帧以内夹到末尾，不借此接受任意越界。

接口冻结：
- buildSubtitleRecipe(segments) 返回新的 RenderRecipe；不修改 segments。
- validateRenderRecipe(recipe) 返回独立的规范化 RenderRecipe，或带 code 的错误。
- SUBTITLE_STYLE 导出当前固定样式参数，供预览与 ASS 转换使用。

### 导出模块：src/video-export.js

小接口隐藏视频探测、ASS 生成、进程、进度和文件保存：
- createVideoExportService({ getExportTools, spawnImpl?, fsApi? })。
- start({ jobId, videoPath, outputPath, recipe }, onProgress) 返回直到终态才 resolve 的 Promise。
- cancel(jobId) 等待对应任务停止；不存在任务时安全返回。
- getState() 返回 idle 或当前任务的 jobId/phase，用于正常关闭应用。

getExportTools 来自同一个 environment 实例，不重新从 PATH 随意选择另一份 FFmpeg。start 内部再次验证配方、路径和实际媒体信息。onProgress 参数为 { jobId, phase, percent }。

Promise 终态统一为 { jobId, status: 'completed' | 'cancelled' | 'failed', outputPath?, errorCode? }。仅 completed 返回最终 outputPath。所有清理完成后才能返回终态。

### 环境模块：src/environment/index.js

增加 getExportTools()，与环境检测共用工具选择和能力探测逻辑。返回 { ffmpegPath, ffprobePath }；不就绪抛 EXPORT_RUNTIME_NOT_READY。

保留 tools.ffmpeg 表达“程序已安装”的事实，增加 modes.subtitleExport 表达硬字幕导出能力。app/env-check.js 在现有模式区域增加“字幕导出”，区分能力缺失和探测失败。原有“继续”按钮不受影响。

当前 Mac 优先检查已安装的 Homebrew ffmpeg-full 标准目录，其次检查既有 FFmpeg 候选。匹配的 ffprobe 与 FFmpeg 来自同一套安装。没有可用组合时明确未就绪。无需扫描任意磁盘目录或自动试遍供应商。

本期候选准备路径为通过现有安装确认流程安装 Homebrew ffmpeg-full；它可能带来较多依赖，先展示实际安装计划、位置、体积估计与耗时再由用户确认。禁止自动强制 link、卸载或覆盖现有 FFmpeg。仍必须实测，包名不能代替能力验证。

### 桌面桥接与界面

main.js 使用主进程原生另存为，构造 outputPath，并调用注入的 videoExportService。preload.js 只公开受限入口：
- resolveVideoSource(videoPath) -> { ok, videoPath?, src?, errorCode? }。
- startVideoExport({ jobId, videoPath, recipe }) -> ExportResult；内部完成另存为，不接受页面的 outputPath。
- cancelVideoExport(jobId) -> Promise。
- onVideoExportProgress(callback) -> 移除监听函数。

app/editor-export.js 负责现有控制器的前置检查、快照、锁与进度交互。已完成任务的 jobId 不再更新新任务。全应用只同时运行一个导出；主进程在打开另存为前占用该位置，取消或失败释放，不建立队列。另存为尚未返回时也可标记取消/关闭；返回后必须先检查该标记和发起窗口是否仍存在，才能启动渲染，防止关闭后启动失去界面控制的任务。

## 6. FFmpeg 执行与文件约定

1. 使用 getExportTools 返回的路径，检查实际输入的视频流、显示尺寸、旋转元数据、时长和音频。竖屏按旋转后的显示尺寸排版；编码宽高与最终观看宽高不得混用。
2. 源路径规范化并确认是本地文件；输出路径来自原生对话框，禁止源/目标相同和已有目标。
3. 建立本次任务的临时目录，字幕写为 UTF-8 ASS。字幕作为纯文本，防止反斜线或花括号被解释成 ASS 样式指令；按解码后文本验收，不以字符串替换后“看起来像转义”代替验证。
4. 临时工作目录内使用固定名称 captions.ass；滤镜引用此固定相对名，用户路径不拼入 filter 字符串。源路径、临时输出路径作为独立参数传入。
5. 同目录创建唯一临时 MP4。用 spawn(program, args, { shell:false })；不使用 cli:exec，不经过 shell，不将 AI 字符串作为命令运行。
6. 保留首个主视频流、首个音频流（音频可无）；输出 H.264/AAC、yuv420p 和 faststart。输入内其他字幕/附件不冒充本软件的已应用效果。
7. 从 FFmpeg 的 progress 输出读取时间并计算百分比；准备和文件提交阶段使用文字状态。进程未结束前百分比最多 99。
8. 成功后先用 FFprobe 验证临时 MP4 可读取、包含视频、有输入音频时仍有音频、时长符合源视频；然后排他创建最终文件，防止覆盖重名文件。
9. 最终保存可采用同目录排他复制 COPYFILE_EXCL，失败仅清理由当前任务新建的残留目标；已有目标不动。进入最终保存后不再接受取消，完成或错误后恢复编辑。
10. 渲染期间收到取消则标记取消并终止当前 FFprobe/FFmpeg 子进程，等待 close，再清理自己的临时文件。进程成功与取消竞争时只能返回一个终态。正常取消限时清理；超时可终止本任务子进程，不能杀死用户其他 FFmpeg。
11. 错误信息简洁地显示在同一浮层。复用现有本地日志，仅记录任务、阶段、错误码和有限诊断；不记录整份字幕、密钥或所有环境变量。

对当前编码不支持的输入属性，失败前明确提示，不擅自缩放或修改原视频。竖屏和普通横屏属于本期验证；HDR 色彩管理、极端尺寸、复杂多视频流不是本期扩展目标。

## 7. 前置能力闸门

此前对本机 /opt/homebrew/bin/ffmpeg 的只读检查：9.0.1_1 配置未列 libass，滤镜列表未找到 subtitles/ass/drawtext。这是已观察到的阻断，当前没有成功的硬字幕导出证据。

周期 0 要对最终选定的同一组工具验证：FFprobe 可运行、当前实际使用的 ass 硬字幕滤镜、libx264、AAC、MP4，并生成一份包含中文字幕与声音的短样片。仅存在 subtitles 而没有 ass 时不能通过当前执行器的检测。短样片使用人工指定字幕，不触发 CLI 或 Whisper。

安装/下载不是当前文档任务的一部分。周期 0 未通过，不进入周期 1 的功能实施。

技术依据（2026-09-06 查阅）：
- FFmpeg subtitles/ass 依赖 libass，并提供字幕文件和字体相关参数：[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html#subtitles-1)。
- 进度输出和流映射使用官方参数：[FFmpeg 文档](https://ffmpeg.org/ffmpeg.html)。
- ffmpeg-full 是包含 libass 等额外依赖的候选发行包：[Homebrew ffmpeg-full](https://formulae.brew.sh/formula/ffmpeg-full)。这不是本机已安装或实际渲染成功的声明。

## 9. 验收与完成等级

目标完成等级为“最低可用”。通过以下检查不等于完成跨平台产品发布。

1. 从首页导入真实有声视频，通过已选本地 CLI 发送“给视频加字幕”，现有本地模型生成字幕。
2. 修改完整字幕文稿并保存；此时导出被阻止。点击应用后预览变化，导出使用该版本。
3. 点击导出，选择新路径；过程中可观看预览和历史，不能修改项目；收起再展开进度仍正确。
4. 导出文件用外部播放器打开，检查修改过的中文、音频、时长和画面尺寸。字幕为硬字幕，不需要播放器加载外部文件。
5. 横屏和竖屏各核对一条长中文字幕，竖屏样片覆盖依靠旋转元数据显示方向的手机素材；按源时间对照开始、中间、结束处的画面，检查文字、位置、相对字号、换行。容许一帧内时间舍入，不以截图哈希要求像素完全相同。
6. 一次取消和一次受控失败：恢复编辑、子进程退出、没有伪成功文件，源视频和已有目标不变。
7. 有未支持时间轴项时明确阻止；删除后不被历史卡片继续阻挡。已有指令在运行时也不能开始导出。
8. 上传 A/B 后重新打开 A：预览和导出都是 A；没有路径或仅有浏览器 Blob 时不假装可导出。
9. 聚焦测试、现有字幕回归与一次真实 Mac 链路通过。模拟 E2E 和真实媒体验收分别记录。
10. 更新研发日志和项目状态，列“内部实现”“用户可见成果”“未完成事项”，附实际输出与检查结果；仅在真实完成后标记通过。
