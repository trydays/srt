## 2. 产品结构与阶段划分

长期结构为两条来源、同一执行流程：常见稳定功能由产品人工决定做成组件；未预设效果由 AI 推敲并生成声明式剪辑配方。组件来源和 AI 来源最终共用项目状态、预览、撤销与导出。

本期只交付字幕这一项真实能力。配方只是从现有已应用字幕创建的一次性、不可变导出快照，必须恰好包含一个 `subtitle.burn@1` 步骤；没有已应用字幕时不提供普通转码出口。现有 subtitle-state 仍是字幕文本、草稿、撤销的唯一存储来源；不新增持久化配方造成双写。

当前 local-cli 的字幕指令继续复用。`version / steps / capability` 只作为当前字幕快照的窄数据边界，不建设注册器、插件、空配方导出或第二个能力。完整 AI 配方生成、原子能力组合、更多真实效果分别在后续有明确样例时计划；不预填未来效果名。

## 3. 用户操作与界面

- 编辑器右上角固定“导出视频”。只在用户点击后渲染。
- 字幕“保存”只持久化草稿；“应用”更新当前字幕与预览。新生成字幕沿用现有自动应用行为，不强迫用户再点一次应用。
- 有未保存或已保存但未应用的字幕时，导出提示“字幕修改尚未应用，请先点击‘应用’”，展开现有字幕编辑区。
- 当前存在淡入等尚未实现真实渲染的时间轴项目时，列出实际名称并阻止导出，不静默忽略。已经删除的时间轴项目不因历史对话仍存在而被误判。
- 字幕/指令正在生成时不可开始导出。当前视频路径缺失、无法播放、不是当前项目实际加载的视频时不可开始导出。
- 原生另存为窗口默认源文件目录、文件名“原文件名-已编辑.mp4”。用户可修改文件名与目录。
- 本期只创建新文件。源文件及其他已有文件均不覆盖；重名时提示换名。取消另存为不启动渲染。
- 输出固定 MP4，内部使用 H.264、AAC、yuv420p；不增加格式、编码器或画质设置。保持正常输入的画面尺寸与时间节奏，不擅自改变帧率。
- 导出按钮显示真实百分比。点击展开锚定式小浮层，包含进度、目标文件、取消按钮。收起不影响运行，不向对话历史追加多条进度消息。
- 准备阶段显示“准备导出”；渲染阶段显示“导出中 N%”；文件提交阶段显示“正在保存”，此时取消按钮禁用；最终显示成功文件路径、取消或可读错误。
- 不模拟百分比。只有子进程正常结束、文件验证及最终保存完成后才显示 100% 和成功。
- 保留现有页面色彩、对话位置与布局，仅增加已确认的导出入口与浮层。

### 导出期间的最小状态约束

允许播放/暂停、拖动播放进度、调整监听音量、浏览历史、展开收起已有内容和进度浮层。

点击导出时取得已应用字幕的不可变快照；之后的输出只读该快照。导出期间禁用用户可见的指令发送、字幕保存/应用/撤销、时间轴增删、重新上传和项目导航入口，避免用户误以为后续修改会进入当前输出。

使用一个页面级 `isExporting` 状态控制上述入口和重复导出；不为每个控制器建设双重权限检查、事件总线或通用任务框架。已有指令运行中不开始导出。取消对话框、失败、取消或成功后恢复入口。

正常关闭应用时只停止本次导出子进程并清理本任务临时文件；另存为返回后若发起窗口已不存在则不启动渲染。不建立后台任务中心、强制退出恢复或系统断电恢复机制。

## 4. 预览、字幕状态与导出保持一致

### 视频来源

目前代码按项目保存 video.path，但预览从 IndexedDB 的全局 current_video 取 Blob。先上传 B 再打开 A 时可能出现“看到 B、导出 A”。

本期局部修正桌面编辑器：通过主进程校验当前项目路径并返回 file URL，播放器加载该源，加载成功后记录当前项目 ID 和规范化路径；识别与导出读取同一个已加载路径。浏览器预览仍可使用 Blob，不迁移 IndexedDB，不建立资产数据库。桌面路径失效不得回退到另一项目的全局 Blob 并继续导出。

### 字幕状态

导出读取现有 store.get(projectId).segments 的深拷贝，不读取 draft 或编辑区的候选文本。导出前检查 hasPendingChanges()，页面进入 `isExporting` 后才获取快照。

### 字幕外观

使用一份固定字幕样式定义，保留当前白字、半透明黑底、居中靠下的视觉。导出模块根据探测后的显示尺寸一次性计算 ASS 字号和边距；配方只快照原始文字与时间，原始显式换行保留，其他自动折行由 libass 在 84% 宽度内完成。不生成浏览器逐行缓存，不建设持续响应 Resize 的排版引擎。

基准为现有 800×450 预览中的 16px 字号、底部 7%、最大宽度 84%、黑底不透明度 0.72。在不同尺寸下按画面高度缩放。当前 Mac 固定使用周期 0 已实测的 `Heiti SC`；不引入字体下载器或字体管理系统。

“最低可用”的一致性验收限于文字、起止时间、颜色、相对位置和相对字号。横屏与竖屏各检查一条常见长句；浏览器与 libass 的精确换行、抗锯齿和圆角边缘不作为本期门槛。若必须增加新渲染技术才能继续，停止报告，不暗中改变产品颜色。

libass 的换行结果不写回用户字幕文本。允许当前预览和 libass 在断行处有细微差异；本期不构建浏览器/libass 共用的 Unicode 排版或 letterbox 内容识别系统。

## 5. 模块与最薄接口

源仓库为 `/Users/mac/Documents/项目/SRTP`；后续实施只在承载 `feature/subtitle-export-cycle0` 的当前 worktree `/Users/mac/Documents/Codex/SRTP-worktrees/subtitle-export-cycle0` 中继续。遵循现有原生 JavaScript、Electron 和 node:test 结构。

### 配方模块：src/render-recipe.js

同一小型纯模块供 Node 与页面使用。职责仅为字幕快照构建、克隆和固定能力校验；不做插件加载、能力注册或通用滤镜语言。

约定输入：`version: 1`，`steps` 必须恰好包含一个 `subtitle.burn@1`。每条字幕只包含 id、以秒为单位的 start/end 和原始 text。配方不包含源路径、目标路径、FFmpeg 参数、排版缓存或脚本。

空 steps、空字幕、未知 capability 或未知版本均明确失败，不顺带建设普通 MP4 转码。时间必须有限、非负且 end > start；实际起止不得超过源视频时长。微小的末尾舍入误差可按一帧以内处理，不借此接受任意越界。

接口冻结：
- buildSubtitleRecipe(segments) 返回新的 RenderRecipe；不修改 segments。
- validateRenderRecipe(recipe) 返回独立的规范化 RenderRecipe，或带 code 的错误。
- SUBTITLE_STYLE 导出当前固定样式参数，供预览与 ASS 转换使用。

### 导出模块：src/video-export.js

小接口隐藏视频探测、ASS 生成、进程、进度和文件保存：
- createVideoExportService({ getExportTools, spawnImpl?, fsApi? })。
- start({ jobId, videoPath, outputPath, recipe }, onProgress) 返回直到终态才 resolve 的 Promise。
- cancel(jobId) 等待对应任务停止；不存在任务时安全返回。
- getState() 返回 idle 或当前任务的 jobId/phase，用于正常关闭应用。

getExportTools 来自同一个 environment 实例，不重新从 PATH 随意选择另一份 FFmpeg。start 内部再次验证配方、路径和实际媒体信息。onProgress 参数为 { jobId, phase, percent, outputPath? }；只有主进程在用户完成另存为选择后发送的 preparing 事件可带 outputPath，供现有浮层显示，不另建任务详情通道。

Promise 终态统一为 { jobId, status: 'completed' | 'cancelled' | 'failed', outputPath?, errorCode? }。仅 completed 返回最终 outputPath。所有清理完成后才能返回终态。

## 6. FFmpeg 执行与文件约定

1. 使用 getExportTools 返回的路径，检查实际输入的首个视频流、显示尺寸、旋转元数据、时长和首个音频流。竖屏按旋转后的显示尺寸排版。
2. 源路径规范化并确认是本地文件；输出路径来自原生对话框，禁止源/目标相同和已有目标。
3. 建立本次任务的临时目录，字幕写为 UTF-8 ASS。字幕作为纯文本，防止反斜线或花括号被解释成 ASS 样式指令；这项用自动测试验证，不在多个周期重复人工取证。
4. 临时工作目录内使用固定名称 captions.ass；滤镜引用此固定相对名，用户路径不拼入 filter 字符串。源路径、临时输出路径作为独立参数传入。
5. 同目录创建唯一临时 MP4。用 spawn(program, args, { shell:false })；不使用 cli:exec，不经过 shell，不将 AI 字符串作为命令运行。
6. 保留首个主视频流、首个音频流（音频可无）；输出 H.264/AAC、yuv420p 和 faststart。输入内其他字幕/附件不冒充本软件的已应用效果。
7. 从 FFmpeg progress 读取真实时间并计算百分比；准备和最终保存使用文字状态。进程未结束前最多显示 99。
8. close=0 后用 FFprobe 做一次最小验证：文件可读、存在视频、有源音频时保留音频、时长基本一致；随后排他创建最终文件，防止覆盖重名文件。
9. 取消只终止本任务当前子进程并清理自己的临时文件；已有目标和源文件不动。最终提交阶段短暂禁用取消，不建设复杂恢复状态机。
10. 错误信息集中显示在导出浮层；只记录阶段、错误码和有限诊断，不建设异常分类平台或自动重试。

对当前编码不支持的输入属性，失败前明确提示，不擅自缩放或修改原视频。竖屏和普通横屏属于本期验证；HDR 色彩管理、极端尺寸、复杂多视频流不是本期扩展目标。

3. 点击导出并选择新路径；浮层显示真实进度，可收起、展开和取消，终态后恢复入口。
4. 外部播放器打开输出，确认修改后的中文已烧录、声音存在、时长和显示尺寸基本一致。
5. 一份普通横屏和一份带旋转元数据的常见手机竖屏验证文字、相对位置和相对字号；不要求精确断行或像素一致。
6. 一次真实取消确认没有伪成功文件且源/已有目标不变。受控失败、A/B 来源一致、未支持项和失效路径由聚焦自动测试证明，不重复手工长视频验收。
7. 只运行与本期相关的 environment、render-recipe、video-export、main-entry、video-export-flow、auto-subtitles 聚焦清单。全量回归仅在剩余支撑额度内限时运行；无关失败只记录，不顺手修复。
8. 更新研发日志和项目状态：完整证据只写一份，项目状态仅写完成等级、可见成果、限制和日志链接。达到以上条件立即停止。

## 10. 后续独立周期

AI 动态配方生成是后续独立产品方向，需要真实指令样例后另定目标、时间与退出条件。Windows 真机、安装包发布、普通无字幕转码、精确跨渲染器排版和更多真实原子能力分别立项；本期不预留开发小时。

自审结论：周期 0 已有真实工具与中文样片证据；剩余设计只保留字幕导出纵切所需的数据快照、渲染、原生保存、进度、取消和源保护。空配方导出、持续排版、通用锁框架、重复人工矩阵和无关全量修复均已移出。
