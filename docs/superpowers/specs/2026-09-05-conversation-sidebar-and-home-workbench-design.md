# SRTP 对话侧栏与工作台首页设计（冻结稿）

状态：2026-09-05 经用户确认。本冻结稿是后续实现的唯一行为依据；预览只作为视觉参考，若两者冲突以本稿为准。新增内容必须重新经过范围闸门。

## 1. 设计结论

自然语言转编辑指令是本产品的核心操作。本地 CLI 被选定后，Agent 负责把用户的话转换为受限编辑指令；产品不再设置另一套独立的“AI 效果翻译”界面。

最终界面采用以下结构：

- 上传素材首页使用“工作台式首页”：紧凑上传入口、最近项目、模板工作流、组件效果预览和清晰的组件库导航。
- 首页右上角显示本地用户头像；点击后打开偏好弹层。弹层只提供“编辑器侧栏位置：左侧 / 右侧”。
- 编辑器使用不遮挡画面的吸附侧栏，默认吸附左侧；用户也可在首页偏好中切换为右侧。
- 侧栏包含“对话 / 组件”两个页签，默认显示“对话”。现有组件能力暂不删除。
- 每次自然语言请求只产生一条用户消息和一张两阶段状态卡；状态在原卡片内更新，不追加多条处理中、成功或失败通知。

## 2. 分阶段范围冻结

两个阶段独立验收。阶段一完成并经用户确认前，不进入阶段二。

### 阶段一：编辑器对话侧栏

1. **唯一目的**：让用户在不遮挡视频的前提下查看并继续项目对话，同时清楚看到自然语言请求从指令转换到时间轴应用的结果。
2. **可直接查看或运行的成果**：编辑器中出现默认左侧吸附的“对话 / 组件”侧栏；首页头像可切换左右位置；对话历史按项目保留；现有“添加淡入”路径以单张两阶段状态卡呈现。
3. **明确不做**：不改造完整首页布局；不做自由浮动窗口；不增加登录、账号或云同步；不删除组件功能；不扩充新的编辑指令；不建设通用 Agent、供应商抽象、自动重试、处理中请求的跨刷新或跨重启恢复，以及复杂恢复系统；不改造导出与渲染流程；不顺手迁移、复活或清理不在当前自然语言路径上的旧云端、Ollama 和命令执行代码。
4. **投入上限**：总实施上限 6 小时；1.5 小时内必须出现可手动操作的吸附侧栏，投入达到 3 小时时必须已经跑通“自然语言 → 单卡状态 → 淡入时间轴标记”的可见闭环；支撑性工作硬上限为 1.5 小时（总投入的 25%）。若支撑模块耗时超过原估计两倍，立即停止并报告。
5. **立即结束条件**：左右吸附、项目历史、单卡状态更新、组件页签和既有淡入时间轴标记通过约定验收后立即结束，不因“还可以更完善”继续追加功能。

本阶段完成等级为**最低可用**：只保证上述核心流程可以运行和手动验证。

### 阶段二：工作台式首页

1. **唯一目的**：在不削弱上传入口的情况下，让首页同时承担继续项目、发现模板和进入组件库的导航职责。
2. **可直接查看或运行的成果**：首页呈现紧凑上传条、占主要视觉空间的最近项目、模板工作流、组件预览带、顶部组件库入口和右上角本地头像。
3. **明确不做**：不新建账号系统、云端项目、推荐算法、模板引擎、组件运行时或数据分析；不重写组件库；不做 FFmpeg 抽帧或时长分析来生成项目缩略信息；不在本阶段扩展编辑器或 Agent 能力。
4. **投入上限**：总实施上限 4 小时；投入达到 2 小时时必须已有可手动查看的首页成果；支撑性工作不得超过总投入的 25%。若支撑模块耗时超过原估计两倍，立即停止并报告。
5. **立即结束条件**：首页信息层级、已有上传流程、最近项目入口、组件库导航和头像偏好入口通过验收后立即结束。

本阶段完成等级为**项目够用**：按当前本地桌面项目规模完善首页，不建设平台级能力。

## 3. 首页体验

### 3.1 顶部导航

从左到右为：品牌标识、工作台、组件库、本地用户头像。

- “组件库”进入现有组件展示页，不另建第二套组件数据或预览系统。
- 头像只在上传素材首页显示；组件库页和编辑器都不显示头像或设置入口。
- 头像是本地入口，不暗示已登录、会员状态或云端同步。

### 3.2 头像偏好

弹层包含本地用户说明和唯一偏好：

- 编辑器侧栏位置：左侧 / 右侧；首次使用默认左侧。该选择是跨项目、跨应用重启保存的本机全局偏好。

弹层不显示“侧栏宽度”或“在编辑器内拖动”等说明。侧栏宽度仍由编辑器中的现有分隔线直接调整，并在本机记忆；它不是头像菜单中的设置项。

### 3.3 工作台内容层级

1. **紧凑上传条**：保留拖入素材和选择文件两种入口，但不再占据大面积首屏空间。
2. **最近项目**：首页最大的内容区，项目卡可直接回到编辑器。卡片只使用当前已有元数据和轻量占位视觉，不为还不存在的缩略图或时长数据新增媒体分析流程。
3. **从模板开始**：只展示少量代表性工作流入口，不在本阶段建设新模板能力。
4. **探索组件效果**：展示少量代表性效果，并用明确按钮进入组件库。

## 4. 编辑器体验

### 4.1 吸附布局

编辑器主体由侧栏、宽度分隔线和视频工作区组成。侧栏占据布局空间并推动工作区缩放，绝不覆盖视频画面。

- 默认顺序：侧栏 → 分隔线 → 视频工作区。
- 右侧偏好：视频工作区 → 分隔线 → 侧栏。
- 初始宽度为约 320 px；沿用现有分隔线的边界约束，避免侧栏或视频区被拖至不可用。
- 调整后的宽度是本机全局偏好；不在头像弹层重复提供宽度控件或说明。

### 4.2 “对话 / 组件”页签

- 默认打开“对话”。
- “对话”显示当前项目的自然语言编辑历史和输入区。
- “组件”承载现有组件搜索、分类和拖入能力。本阶段只改变其容器位置，不删除或扩展能力。
- 切换页签不改变视频、时间轴或当前播放位置。

### 4.3 项目对话历史

历史记录按项目隔离并在本机持久保存。项目 A 的消息不会出现在项目 B。

最小持久化内容包括：用户原始文本、提交时间、指令转换最终状态、时间轴应用最终状态。只有进入成功、失败或未执行等最终状态的记录才进入持久历史；“转换中 / 等待 / 应用中”只属于当前页面状态，刷新或关闭后不恢复、不续跑，也不自动重试。

新建项目获得稳定的本地项目标识，并用一个本机 `active project id` 明确当前项目。打开首页项目卡或项目标签时，必须先更新当前项目标识再进入编辑器。旧项目首次读取时补充标识并保存，避免以项目名称或共同的 `剪辑.html` 路径作为唯一键。数据继续使用现有本地存储方式，不引入数据库或云服务。

本阶段的“按项目保存”只覆盖对话历史。视频元数据和素材 Blob 继续沿用当前全局存储方式；把视频素材改为按项目隔离属于独立的数据迁移，不得顺手加入本阶段。

## 5. 单条两阶段状态卡

一次用户请求只占用以下两项：

1. 一条用户消息，原样显示自然语言。
2. 紧随其后的一张状态卡，包含两行阶段状态。

状态机如下：

| 时刻 | 转换编辑指令 | 应用到时间轴 |
|---|---|---|
| 请求刚提交 | 转换中 | 等待 |
| 指令合法返回 | 成功 | 应用中 |
| 时间轴更新完成 | 成功 | 成功 |
| 指令转换失败 | 失败 | 未执行 |
| 时间轴应用失败 | 成功 | 失败 |

状态卡始终原位更新：

- 不再单独追加“正在转换编辑命令”“生成中”“成功”或“失败”消息。
- 转换失败时不执行后续步骤，也不修改时间轴。
- 时间轴应用成功后才出现对应标记；应用失败不留下新标记。
- 当前能力没有生成成品视频，因此界面不使用“视频生成中 / 视频生成成功”。
- 失败卡默认只显示简短、可行动的错误摘要；本阶段不建设复杂日志面板或自动重试机制。

## 6. 最小数据与接入边界

沿用现有页面和脚本，避免为本次 UI 改造建立新平台层：

- `app/主页.html`：阶段一只增加头像及偏好弹层；阶段二再调整工作台布局。
- `app/剪辑.html`：承载吸附侧栏、页签和状态卡结构。
- `app/editor-core.js`：复用现有组件列表与分隔线行为。
- `app/editor-timeline.js`：复用现有自然语言提交、`translateLocalCliEffect` 和时间轴标记路径；将多条消息改为单卡状态更新。
- `app/shared.js`：增加最少的全局偏好、稳定项目标识、当前项目标识与项目历史存储键；继续使用 `localStorage`。

侧栏与状态卡只在 renderer 内实现，不新增 main / preload / CLI 接口。自然语言分支直接使用真实 Promise 状态；时间轴应用当前是同步操作，不为展示“应用中”而引入假延迟或任务队列。

当前已验证的指令契约保持不变：

```js
{ type: 'add_effect', effect: 'fade_in' }
```

本设计不扩大该指令白名单，也不改变 main / preload 的安全边界。

## 7. 验收

### 阶段一验收

- 首次进入编辑器，侧栏默认在左侧且不遮挡视频。
- 首页头像弹层只显示侧栏位置偏好；切换到右侧后重新进入编辑器仍保持右侧。
- 编辑器内可拖动分隔线调整宽度；重新打开项目后宽度保持，头像弹层中没有宽度项。
- “对话 / 组件”均可切换，现有组件搜索和拖入行为未退化。
- 提交“给片头添加一个淡入效果”后，只新增一条用户消息和一张状态卡；卡片依次更新为两项成功，并出现一个淡入时间轴标记。
- 指令转换失败时，同一卡显示“失败 / 未执行”，且时间轴不变。
- 两个项目的历史互不串用；重开应用后已完成历史仍可见。
- 统一侧栏在 Electron 的最小窗口宽度附近仍可访问，不沿用会把整个侧栏隐藏的旧响应式规则。

自动检查只覆盖以上关键路径，并将效果/侧栏用例纳入项目实际执行的 E2E 脚本，避免出现“测试文件存在但默认测试命令未运行”的假通过；不为处理中断、跨重启恢复或其他未列入验收的边缘场景增加产品状态与测试管线。另做一次桌面端手动检查，确认常用窗口宽度下视频未被侧栏覆盖、拖宽可用，并能看到真实请求的处理中状态。

### 阶段二验收

- 上传入口仍支持点击与拖入，原有素材写入和进入编辑器路径不变。
- 最近项目是首页视觉主体，并可沿用现有方式打开当前项目；本阶段不承诺把视频素材改造成多项目独立存储。
- 顶部和组件预览区都能进入现有组件库。
- 头像偏好入口可用，且没有登录或云同步暗示。
- 常用桌面窗口下，无横向溢出或主要按钮被遮挡。

## 8. 强制止损与报告格式

任何新增工作只有满足下列任一条件才能进入当前阶段：

- 不做就无法通过上述既定验收；
- 不做会造成现实的安全、法律或数据损失风险；
- 用户了解成本后明确批准加入。

否则放入“以后再做”，不得顺手实现。每次阶段报告同时列出：

- **内部完成度**：代码与自动检查完成到何处。
- **用户可见成果**：用户现在能够打开、查看和手动验证什么。

达到验收条件即停止，不以可靠性、安全性、可恢复性或复用性为由继续扩张。

两阶段共同遵守以下硬规则：支撑性工作不得超过 25%；任何支撑模块超过预估两倍立即停下来报告；新增边界测试不得自行扩大验收范围；连续两个阶段不得都只产生内部代码或测试；达到验收后禁止继续镀金。

## 9. 以后再做

- 自由浮动、跨窗口或多面板对话。
- 处理中请求的跨刷新、跨重启恢复、续跑或自动重试。
- 登录、账户、会员、云同步和跨设备偏好。
- 通用多供应商 Agent、复杂并发、自动恢复和重试队列。
- 使用帮助导航及帮助内容。
- 新的模板系统、组件市场、推荐或分析能力。
- 视频素材与 Blob 的多项目独立存储迁移。
- 淡入之外的新编辑指令与真实视频导出扩展。
- 删除组件入口或彻底以对话取代组件工作流。
