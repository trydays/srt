# SRTP 本地 CLI 检测与选择设计（冻结范围）

## 目标与边界

SRTP 是 Electron + Remotion 的自然语言视频剪辑应用。后续阶段会让用户选定的本地 CLI 将自然语言转换为精确剪辑指令，并由 Remotion 作为渲染核心；该能力只是背景，**本期不得实现或预埋调用链**。

本期只做一件事：扫描本机可用的 Codex CLI、Claude Code、Gemini CLI 三种固定工具，并让用户明确选择其中一个作为全局本地默认值。CLI 集成始终是可选能力；扫描、选择失败或未选择均不得阻止进入或使用 SRTP 的其他部分。

本期不做：CLI 调用、自然语言转编辑命令、Remotion 执行集成、安装、认证/登录、模型选择、更多 CLI 或自定义注册表、平台/插件抽象、穷举并发或失败恢复、真实 Windows E2E、复杂 Windows 引用框架、特殊文件对象或符号链接链校验、自定义合并流进程运行器、原子偏好写入、handler 调用次数断言、动态场景或重启测试框架。

## 固定目录与可用性

扫描目录、显示名称和探测参数都是内部固定定义，页面、偏好文件和用户输入均不能扩展它：

| id | 显示名 | 命令 | 探测 |
| --- | --- | --- | --- |
| `codex` | Codex CLI | `codex` | `--version` |
| `claude` | Claude Code | `claude` | `--version` |
| `gemini` | Gemini CLI | `gemini` | `--version` |

扫描器按固定顺序检查三个定义。它只搜索普通 `PATH`，以及少数现有、常见安装目录：macOS 的 `/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`、`$HOME/.local/bin` 和现有的 Codex desktop app 常见位置；Windows 保留 `Path`/`PATHEXT` 与常见 Node/npm 安装目录的最小兼容分支。不得递归扫描磁盘、家目录或用户指定位置。

候选项以固定 `--version` 进行短超时探测；零退出码表示“可用”。单项失败不得影响其余项。版本内容无需解析、保存或显示。结果只返回成功项，按上表顺序稳定排列，不返回路径、环境、输出、认证或诊断数据。

macOS 是本期唯一的真实设备验证目标。Windows 分支仅保持最小的路径与探测兼容性，并以有针对性的单元测试覆盖；本期不得宣称完成平台级 Windows 验证。

## UI 与用户流程

在现有环境检测页面增加“本地 CLI”区域，并始终显示：`目前仅支持 Codex CLI、Claude Code 和 Gemini CLI。`

1. 页面加载时获取扫描结果和已保存选择；扫描中可显示“正在扫描本地 CLI…”。
2. 只为成功检测的 CLI 显示可选择卡片。卡片仅需显示固定名称与可用状态。
3. 没有成功项时，结果区域必须精确显示：`未扫描到可用本地 CLI`。
4. 不显示缺失工具的灰卡、安装入口、登录/认证入口或模型控制。
5. 用户必须主动点击可用卡片才能设为默认；不得首次自动选择、不得因重新扫描自动切换到另一项。
6. 用户可重新扫描。若已选 CLI 仍被检测到，保留选择；若未被检测到，清除选择并要求用户再次明确选择。
7. 扫描或选择错误可提供简洁重试反馈，但任何状态都不能阻断进入主页或编辑器。

## 选择与持久化

主进程保存一个全局本地默认值 `selectedCliId`，其值只能为 `null`、`codex`、`claude`、`gemini`。持久化可以采用简单的 Electron 用户数据目录偏好文件。

选择接口只接受当前扫描成功的固定 id。未知 id、未成功检测的 id 或无效输入不得改变现有有效选择。每次读取状态或重新扫描都以最新成功结果复核保存的选择；若已选 id 不在结果中，立即清除为 `null`。没有任何自动选择或自动替代规则。

建议只暴露专用的读取、重扫和选择接口；renderer 不应获得文件系统、环境变量、路径、版本输出或任意命令执行能力。状态形状保持最小：

```js
{
  available: [{ id: 'codex', label: 'Codex CLI' }],
  selectedCliId: 'codex' // 或 null
}
```

## 测试与人工验证

实现阶段采用以下足够的验证范围：

- 扫描器和选择/失效逻辑的聚焦单元测试，覆盖三项固定定义、仅返回成功项、无自动选择、显式选择持久化及已选项消失后的清除；Windows 只覆盖最小路径/探测分支。
- 一条 Electron E2E 空状态场景，验证精确文案、无缺失工具卡片，以及仍可进入软件。
- 一条 Electron E2E 可见的“选择并持久化”场景，验证用户明确选择后可恢复该默认值。
- 在本 Mac 上完成手工扫描、选择、重扫及失效清除检查。

无需为本期构建复杂测试基础设施或真实 Windows E2E。

## 时间控制与停止规则

- 实施开始后 60–90 分钟内必须出现可见页面检查点。
- 总投入硬上限为 3 小时。
- 支持/基础设施工作不超过总投入的 25%。
- 若支持工作超过原估计的 2 倍，停止并报告，不扩大实现。
- 验收通过即停止，不顺带实现后续能力。

## 完成标准

本期仅在以下全部满足时完成：

- 三种固定 CLI 被扫描，且页面只显示成功检测到的结果。
- 空状态精确显示“未扫描到可用本地 CLI”。
- 选择只能由用户明确作出、可持久化，且从不自动选择或切换。
- 先前选中的 CLI 消失时，选择被清除并要求重新明确选择。
- CLI 始终可选，不影响 SRTP 其他功能的进入和使用。
- 聚焦测试与本 Mac 的手工验证通过。

随后如要实现“所选 CLI 将自然语言翻译成精确编辑指令，并由 Remotion 渲染”，必须单独立项、设计和验收。
